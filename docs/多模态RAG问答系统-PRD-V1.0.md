## 1. 产品摘要

### 1.1 一句话定义

面向企业知识分析和研究团队，将 PDF 等复杂文档自动解析为可检索、可验证的知识图谱，并通过 Agentic-RAG 提供带原文引用与版面定位证据的问答工作台。

### 1.2 产品核心价值

| 价值 | 用户结果 |
| --- | --- |
| 降低阅读成本 | 自动提取实体、关系、指标和证据，用户不必逐页人工摘录 |
| 提高知识复用 | 文档、实体、关系、图谱和问答结果形成结构化资产 |
| 建立答案信任 | 每个回答可追溯到文档、页码、字符区间和 bbox |
| 缩短分析周期 | 自然语言提问直接定位跨页信息与表格数值 |
| 降低运维复杂度 | 解析、抽取、图谱构建和问答状态可视化，可取消、重试和审计 |

### 1.3 产品定位

产品不是通用聊天机器人，也不是完整的文档编辑器。它是一套“文档进入 → 结构化知识形成 → 证据驱动问答”的知识生产工作台。

V1 的核心闭环：

```text
上传文档
  → 自动解析与建图
  → 查看抽取结果
  → 探索知识图谱
  → 对选中文档提问
  → 查看答案与原文证据
  → 继续追问或导出结果
```

## 2. 项目背景、目标与业务痛点

### 2.1 项目背景

研究报告、技术文档、财报、合同、投标文件、运维报告等材料通常同时包含正文、表格、公式和图片。传统全文检索只能返回文本片段，通用聊天模型又难以保证事实来自指定文档。现有后端已经具备：

- MinerU 文档解析与版面信息；
- LangExtract 实体/关系抽取；
- Bridge Pipeline 生成节点、边和溯源；
- LangChain + MCP + DeepSeek 的 Agentic-RAG；
- 分页、字符区间、bbox 和图谱快照等可追溯数据。

当前缺口是面向真实用户的产品层：上传、进度、质量控制、结果核验、图谱探索、引用回看和任务运维缺少统一体验。

### 2.2 业务痛点

| 痛点 | 当前表现 | 产品解决方式 |
| --- | --- | --- |
| 文档阅读效率低 | 数十至上百页材料依赖人工检索和摘录 | 自动解析 + 实体关系抽取 |
| 数据散落 | 正文、表格和结论难以建立关联 | 统一页、块、节点、关系模型 |
| 回答不可信 | 通用模型无法证明结论来自指定文档 | 强制引用、原文切片和版面高亮 |
| 多组件链路黑盒 | 用户不知道解析在哪个阶段失败 | 任务阶段、进度、日志与可恢复错误 |
| 结果难复核 | 只有一段回答，没有证据与定位 | 引用抽屉、页内高亮、图谱节点溯源 |
| 知识难复用 | 每次提问重新读文档 | 持久化文档、抽取和图谱快照 |
| 不同格式质量不一 | Office/图片解析与图谱适配能力不一致 | 明确能力标签、`graph_v1/parse_only` 分级 |

### 2.3 产品目标

#### 业务目标

1. 让用户在一个工作台内完成文档到答案的完整任务。
2. 让每一次有事实依据的回答都可回溯到原文。
3. 让解析和建图链路可观察、可重试、可审计。
4. 为后续多文档知识库、团队协作和问答 API 建立产品基础。

#### 用户目标

- 3 分钟内完成首份 PDF 上传并理解当前处理状态；
- 在结果页 1 分钟内找到关键实体及其原文位置；
- 通过自然语言问出跨段、跨表格知识；
- 点击引用后 2 次以内回到证据原文；
- 失败时能知道原因和下一步动作。

### 2.4 非目标

V1 不包含：

- 文档在线协同编辑与批注；
- 自动生成完整知识库报告；
- 视觉问答或图片 Embedding；
- 默认启用向量数据库；
- 跨租户知识共享；
- 完全自动的业务决策；
- 对未验证格式承诺同等建图质量。

## 3. 目标用户与核心场景

### 3.1 用户角色

| 角色 | 典型职责 | 主要需求 | 权限 |
| --- | --- | --- | --- |
| 业务分析师 | 阅读行业报告、财报、调研材料 | 快速抽取实体、指标和结论 | 上传、查看、问答、导出 |
| 研发/技术人员 | 分析技术规范、故障报告、方案文档 | 查设备、关系、指标和出处 | 上传、查看、问答、高级轨迹 |
| 合规/审计人员 | 复核事实与原始依据 | 检查引用、页码、原文和版本 | 查看、审计、下载证据 |
| 知识库运营 | 维护文档和索引质量 | 重索引、失败处理、监控 | 任务管理、删除、重试 |
| 系统管理员 | 管理租户、配额和服务连接 | 运行状态、权限、配置 | 管理设置、审计 |
| 外部集成开发者 | 将能力接入其他系统 | 稳定 API、任务、引用格式 | API Client |

### 3.2 核心场景

#### 场景 A：单文档知识提取

分析师上传一份年度报告。系统显示解析和建图阶段，完成后展示页数、内容块、实体、关系和丢弃原因。分析师在图谱中点击“Pine Creek”，看到其实体类型、证据、页码与关联指标。

成功标准：

- 用户能判断索引是否成功；
- 用户能查看抽取质量；
- 用户能定位实体原文。

#### 场景 B：证据驱动数值问答

用户选中一份或多份已索引文档，询问“Pine Creek 的年降雨量、径流量和径流比分别是多少”。Agent 调用实体、页文本和证据工具，返回答案、表格数值与结构化引用。用户点击引用，在右侧原文面板看到页内高亮与 bbox。

成功标准：

- 回答数值正确；
- 至少有一条可验证引用；
- 证据不足时明确拒答。

#### 场景 C：报告失败排查

文档解析失败。用户在任务详情中看到失败阶段、错误码、是否可重试和上游任务 ID。运营人员可以重试或下载已生成产物，不必重新上传文件。

成功标准：

- 用户知道“哪里失败”和“能否重试”；
- 不暴露 Token、内部路径或敏感堆栈。

#### 场景 D：格式准入与降级

用户选择 DOCX。界面在前置检查阶段提示“当前版本可解析，但 Graph V1 尚未开放”，允许选择仅解析并保留产物。用户不会在上传完成后才发现无法问答。

成功标准：

- 格式能力在提交前透明；
- 不把 parse-only 文档误显示为可问答。

## 4. 产品范围与成功指标

### 4.1 V1 核心范围

| 模块 | P0 必做 | 说明 |
| --- | --- | --- |
| 上传 | 是 | 上传会话、校验、PDF Graph V1 |
| 异步任务 | 是 | 排队、解析、抽取、建图、成功/失败 |
| 文档库 | 是 | 状态、搜索、筛选、重试、删除 |
| 文档详情 | 是 | 概览、解析信息、抽取、图谱、产物 |
| 图谱探索 | 是 | 节点/边、筛选、邻居、详情、原文证据 |
| 问答 | 是 | 单/多文档 scope、回答、引用、拒答 |
| 原文证据面板 | 是 | 页码、字符区间、bbox、文本切片 |
| 任务中心 | 是 | 进度、阶段、错误、取消、重试 |
| 管理设置 | P1 | 服务状态、配额、模型和解析器信息 |
| Office/图片 Graph V1 | P1 | 依赖 Normalizer 适配与质量验收 |
| 可视化产物导出 | P1 | PNG/SVG/JSON/引用清单 |

### 4.2 格式能力展示规则

界面必须按真实能力展示，不能让用户把“可解析”理解成“可建图问答”。

| 能力标签 | 含义 | UI 行为 |
| --- | --- | --- |
| `可建图` | 当前版本 Graph V1 已通过验证 | 可选择 `graph_v1`，完成后可问答 |
| `仅解析` | MinerU 可解析，但未接入 Graph V1 | 可选择 `parse_only`，结果不可问答 |
| `暂不支持` | 当前后端不接收 | 选择文件后立即提示，不创建任务 |

### 4.3 成功指标

#### 产品指标

| 指标 | 上线目标 |
| --- | --- |
| 首份 PDF 上传成功率 | ≥ 98%（排除上游故障） |
| 上传后 10 秒内出现明确排队/处理中反馈 | 100% |
| PDF 建图任务成功率 | ≥ 95%（测试集） |
| 回答至少一条有效引用比例 | ≥ 95%（可回答问题） |
| 无证据问题正确拒答率 | ≥ 95% |
| 引用点击可定位原页/切片成功率 | ≥ 99% |
| 失败任务具备可理解错误说明比例 | 100% |
| 关键页面无阻塞性前端错误 | 100% |

#### 体验指标

| 指标 | 目标 |
| --- | --- |
| 从上传完成到结果页可查看进度 | < 1 秒 |
| 文档/任务状态查询 P95 | < 200 ms |
| 图谱首屏渲染 | ≤ 2 秒（≤100 节点） |
| 问答首条反馈 | ≤ 2 秒 |
| 问答完整返回 P95 | ≤ 30 秒 |
| 移动端上传到提交 | ≤ 3 次点击 |

#### 质量指标

- 抽取结果对齐状态可见；
- 图谱悬空边、无依据实体有统计；
- 表格数值回答保留原始单位与表头；
- 不把日志中的 Token、Key、内部路径展示给普通用户。

## 5. 信息架构与导航

### 5.1 一级信息架构

```text
EvidenceGraph
├── 工作台 /
│   ├── 快速上传
│   ├── 最近文档
│   ├── 运行中任务
│   └── 最近问答
├── 文档 /documents
│   ├── 文档列表
│   └── 文档详情 /documents/:documentId
│       ├── 概览
│       ├── 解析内容
│       ├── 抽取结果
│       ├── 知识图谱
│       ├── 问答
│       └── 产物与任务
├── 图谱 /graph
│   └── 多文档图谱探索
├── 问答 /ask
│   ├── 会话列表
│   ├── 消息线程
│   └── 引用/原文侧栏
├── 任务 /jobs
│   ├── 运行中
│   ├── 成功
│   └── 失败/重试
└── 管理 /admin
    ├── 服务状态
    ├── 格式能力
    ├── 模型与解析器
    └── 审计与配额
```

### 5.2 导航规则

- 桌面端使用左侧 240 px 固定导航；
- 当前页面项目高亮，不使用纯颜色作为唯一提示；
- “文档详情”内部使用顶部二级标签页，切页不丢失筛选和图谱选中状态；
- 全局任务中心显示运行中任务数量，但每分钟最多提示一次状态变化；
- 问答和原文证据采用双栏，移动端改为上下堆叠和底部抽屉。

## 6. 端到端产品流程

### 6.1 主流程总览

```text
入口/登录
  → 工作台
  → 上传文件
  → 前端预检
  → 创建上传会话
  → 上传文件
  → complete 创建索引任务
  → 实时进度/代理轮询
  → 解析完成
  → 抽取完成
  → 图谱快照发布
  → 文档 indexed
  → 结果核验
  → 选择问答 scope
  → 提问
  → Agent 工具检索
  → 回答 + 结构化引用
  → 原文定位
  → 追问/导出
```

### 6.2 流程 1：进入与身份校验

1. 用户打开系统。
2. 无有效会话时进入登录页。
3. 登录成功返回原目标页面；无目标则进入工作台。
4. 系统加载当前租户、用户角色和只读/可写能力。
5. 服务未就绪时展示阻断页和重试，不进入半可用状态。

异常：

- `401`：清空本地令牌，跳转登录；
- `403`：显示无权限页，不循环请求；
- `503`：展示“知识服务暂不可用”，保留最近成功缓存页面并禁止新任务。

### 6.3 流程 2：上传与预检

1. 用户点击拖拽区或选择文件。
2. 前端读取文件名、扩展名、MIME、大小。
3. 前端本地预检：
   - 文件是否存在；
   - 扩展名是否在能力表；
   - 是否超过浏览器建议限制；
   - `graph_v1` 是否适用于该格式。
4. 对可解析但不支持 Graph V1 的格式，展示能力提示：
   - “仅解析并保存”；
   - “取消”；
   - 若后端 feature flag 关闭，则直接阻止。
5. 用户确认抽取 profile、语言、OCR、表格、公式和页码范围等高级选项。
6. 前端调用 `POST /api/v1/uploads` 创建会话。
7. 按后端返回使用 presigned URL 或本服务内容端点上传。
8. 上传进度显示百分比；失败提供“重试上传”和“更换文件”。
9. 上传完成调用 `POST /uploads/{id}/complete`。
10. 服务端返回 `document_id/job_id`，页面切换到任务进度视图。

前端预检不能替代服务端校验。服务端仍负责 MIME、文件头、SHA、大小和页数检查。

### 6.4 流程 3：解析与建图进度

1. 页面订阅 `GET /jobs/{job_id}/events`；不支持 SSE 时每 1.5–2 秒轮询 `GET /jobs/{job_id}`。
2. 进度条只反映当前 job 的总进度，阶段列表显示：
   - 文件校验；
   - MinerU 提交；
   - 云端解析；
   - 产物下载；
   - 内容归一化；
   - 知识抽取；
   - 图谱构建；
   - 快照发布。
3. `warning` 事件显示为可展开提示，不把进度条永久变成失败色。
4. 用户可取消任务；取消后显示已生成产物和不可继续原因。
5. `completed` 事件到达后，重新拉取文档详情和 graph manifest。
6. 页面只在新 snapshot active 后启用“开始问答”。

### 6.5 流程 4：结果核验

1. 进入文档详情的“概览”页。
2. 查看摘要卡：页数、内容块、节点、边、丢弃原因、耗时。
3. 进入“抽取结果”查看实体和关系列表。
4. 搜索或按类型筛选。
5. 点击实体：
   - 右侧显示实体属性；
   - 显示页码、字符区间、bbox、evidence；
   - 可选择“定位原文”；
   - 可选择“在图谱中查看”。
6. 进入“知识图谱”查看网络、图例和邻接关系。
7. 进入“产物”查看 `content_list/layout/nodes/edges/provenance`，受权限时可下载。

### 6.6 流程 5：提问与回答

1. 用户从文档详情或全局问答页创建一个会话。
2. 选择题问 scope：单文档或多文档。
3. 输入问题；前端限制 1–4000 字符。
4. 提交 `POST /qa/answers`，或使用 `POST /qa/answers:stream`。
5. 流式阶段依次显示：
   - 正在检索实体；
   - 正在扩展关系；
   - 正在查看页面证据；
   - 正在生成答案。
6. 工具调用超过 2 秒时，显示非阻塞的“Agent 正在检索”状态，不冻结输入区。
7. 答案完成后：
   - 有证据：显示答案和 `citations[]`；
   - 证据不足：显示 `insufficient_evidence` 和检索过的范围；
   - 失败：显示错误与可重试按钮。
8. 用户点击引用，右侧原文面板打开对应页，滑动并高亮字符区间与 bbox。
9. 用户可继续追问，scope 不变，直到手动修改。
10. 用户可导出答案、引用清单和证据。

### 6.7 流程 6：失败、重试与恢复

#### 上传失败

- 断网：保留文件元数据，提供重试；
- 413：提示实际限制并建议压缩、拆页或切换能力；
- 415：显示格式能力表；
- checksum mismatch：重新上传；
- 会话过期：重新获取上传会话。

#### 解析/建图失败

- 在阶段条中标记第一个失败阶段；
- 展示脱敏后的错误码、用户说明、是否可重试；
- `retryable=true` 显示“重试任务”；
- 提供“查看诊断”面向有权限用户；
- 不显示原始 API Key、完整上游响应、内部绝对路径。

#### 问答失败

- 429：建议稍后重试并展示冷却时间；
- 504：保留问题，可一键重试；
- 引用校验失败：不展示未经校验的链接；
- 图谱未就绪：禁用提问并跳转到任务详情。

### 6.8 流程 7：重索引与版本

1. 文档详情右上角选择“重新索引”。
2. 系统展示当前 snapshot、要使用的抽取配置和新任务说明。
3. 新任务运行期间，当前 active snapshot 仍可查询。
4. 新 snapshot 成功后按 `activate_on_success` 原子切换。
5. 用户可查看版本历史并对比节点/边数量、质量告警和生成时间。
6. V1 不要求可视化图谱 diff；至少支持 manifest 与统计对比。

## 8. 页面详细说明

### 8.1 工作台 `/`

#### 页面目标

让用户在 10 秒内开始上传，同时了解当前知识库运行状态和最近工作。

#### 页面结构

1. 顶部欢迎区：租户、当前角色、服务状态；
2. 主上传卡：拖拽/选择文件、能力提示、最近一次安全配置；
3. 运行中任务：最多 3 条，显示阶段、进度、耗时；
4. 最近文档：状态、文件类型、更新时间、问答入口；
5. 最近问答：问题摘要、grounded、引用数、继续会话；
6. 质量提示：解析告警、失败任务、格式适配状态。

#### 主操作

- 上传并建图；
- 上传仅解析；
- 查看最近文档；
- 继续问答；
- 打开任务中心。

#### 空状态

```text
尚无知识文档
拖入一个 PDF 开始构建可追溯的文档知识图谱。
[选择 PDF] [查看支持格式]
```

#### 验收

- 上传失败原因立即可见；
- 同一页面同时展示处理中和已索引的状态；
- 不需要先进入文档库才能开始上传。

### 8.2 文档库 `/documents`

#### 页面目标

集中管理文档、检索状态和后续动作。

#### 页面结构

- 页面标题、数量、搜索框；
- 筛选：状态、格式、能力 `graph_v1/parse_only`、时间；
- 文档表格/卡片混合视图；
- 批量操作区（P1）；
- 分页游标或“加载更多”。

#### 文档行字段

| 字段 | 展示 |
| --- | --- |
| 文件名 | 图标 + 文件名 + MIME |
| 能力 | `可建图`/`仅解析` |
| 状态 | queued/parsing/extracting/indexed/failed |
| 规模 | 页数、节点、边 |
| 时间 | 创建、更新 |
| 主操作 | 查看、问答、重试、删除 |

#### 交互

- 文件名点击进入详情；
- `indexed` 文档行显示“提问”；
- 失败行显示错误摘要与重试；
- 删除需二次确认，明确会移除图谱和产物；
- 搜索输入 300 ms 防抖，保留 URL 参数便于分享。

### 8.3 文档详情 `/documents/:id`

#### 顶部固定区域

- 返回文档库；
- 文件名、格式、大小、更新时间；
- 状态和 active snapshot；
- `提问`、`重新索引`、更多菜单；
- 二级 Tab：概览 / 解析内容 / 抽取结果 / 知识图谱 / 问答 / 产物与任务。

#### 8.3.1 概览

- 6 个指标卡：页数、内容块、实体、边、有效引用数（问答统计）、处理耗时；
- MinerU 解析概况：模型版本、语言、表格/公式开关、告警；
- 图谱概况：节点类型分布、关系类型分布、丢弃原因；
- 最近任务时间线；
- 数据质量提示：
  - `full.md` 可能缺块；
  - 未对齐抽取数；
  - 悬空关系数；
  - 无引用节点数。

#### 8.3.2 解析内容

- 左侧页目录或缩略页；
- 中间 Markdown/结构化块预览；
- 右侧块详情：`type/text/table_html/page_idx/bbox`；
- 明确标识“可视化渲染”与“权威块数据”；
- 支持点击块定位图谱节点（有映射时）。

#### 8.3.3 抽取结果

- 顶部 KPI：实体数、关系数、对齐状态分布；
- 筛选：搜索、类型、页码、alignment status；
- 实体列表与关系列表可切换；
- 点击条目打开检查器；
- 图谱跳转和原文定位。

#### 8.3.4 知识图谱

- 画布占主区；
- 右侧检查器 360 px；
- 顶部筛选：节点类型、关系类型、页号、度数；
- 图例和缩放；
- 节点/边详情；
- 可以在文档内图谱与多文档图谱间切换。

#### 8.3.5 问答

- 嵌入问答面板；
- 默认 scope 为当前文档；
- 显示当前 graph snapshot；
- 回答中的引用可打开原文面板；
- 可以从详情页无缝继续到全局问答页。

#### 8.3.6 产物与任务

- 当前和历史的 job；
- 产物分组：解析文件、抽取文件、图谱文件、诊断文件；
- 文件大小、schema、SHA 前 12 位；
- 按权限下载。

### 8.4 图谱探索 `/graph`

#### 页面目标

让用户围绕一个实体及邻接关系进行探索，而不是只看静态图。

#### 结构

1. Scope 栏：文档选择器、快照、节点数；
2. 左侧筛选器：类型、页号、度数、证据状态；
3. 中央画布；
4. 右侧检查器；
5. 底部状态条：缩放、节点数、当前选择。

#### 画布规则

- 节点颜色按实体类型；
- 节点大小表示度数，但保留最大尺寸；
- 边箭头表示方向；
- 选中节点高亮直接边；
- 悬停显示名称；
- 双击节点展开 1 层邻居；
- 拖拽节点调整位置，滚轮缩放，空白拖拽平移；
- 节点超过 300 个时默认只渲染当前深度的子图。

#### 右侧检查器

- 名称、别名、类型、页码；
- `char_interval`、`bbox`、`bbox_pdf`；
- evidence；
- attributes；
- 关联关系和邻居；
- 操作：定位原文、以该节点为 scope 提问、筛选子图。

### 8.5 问答工作台 `/ask`

#### 页面目标

以最小操作获得可信回答，并随时查看证据。

#### 结构

```text
┌──────────┬──────────────────────────────┬─────────────────────┐
│ 会话历史 │ 问题与答案线程               │ 引用/原文证据       │
│          │                              │                     │
│ 新会话   │ [用户] 问题                  │ 页 1               │
│ 继续...  │ [系统] 答案                  │ 高亮文本            │
│          │ [引用 1] [引用 2]            │ bbox 可视化         │
│          │ 工具轨迹（可折叠）           │ 打开原文档          │
│          │ [输入框] [发送]              │                     │
└──────────┴──────────────────────────────┴─────────────────────┘
```

#### Scope 栏

- 文档 chips；
- 最多 10 个；
- 每个 chip 显示文件名、indexed 状态；
- 不可用文档禁用并解释；
- scope 变化后提示“将开启新的检索上下文”。

#### 回答卡片

- 回答正文；
- grounded 徽标；
- citation chips；
- “证据不足”态；
- 工具轨迹折叠区；
- token/耗时只在高级视图显示。

#### 输入区

- 多行文本，支持 Shift+Enter 换行，Enter 发送；
- 发送中显示停止/重试；
- 问题超过 4000 字时阻止并给出限制；
- 不允许空问题；
- 输入时保持最近 scope 提示可见。

#### 原文证据面板

- 页标题和页码；
- 命中片段；
- 字符区间；
- bbox 在页面预览上高亮；
- 复制引用；
- 打开文档详情；
- 找不到定位时显示“有文本证据，无版面坐标”，不伪造高亮。

### 8.6 任务中心 `/jobs`

#### 页面目标

让运营和用户快速识别阻塞、失败和长时间运行任务。

#### 结构

- 统计：排队、运行、失败 24h、平均耗时；
- 筛选：状态、阶段、文档、时间；
- 表格；
- 右侧任务详情抽屉；
- 阶段时间线和事件流；
- 重试/取消/复制诊断信息。

#### 任务字段

`job_id, document, status, stage, progress, attempt, started_at, finished_at, error_code, retryable`

#### 错误展示

面向普通用户显示：

```text
知识抽取失败
文档已成功解析，但在实体/关系抽取阶段失败。
[重试任务] [查看已生成产物]
```

面向运营可展开：

```text
code: EXTRACTION_FAILED
stage: extract
attempt: 1
retryable: true
request_id: req_...
```

### 8.7 管理设置 `/admin`

P1 页面，包含：

- MinerU 解析状态与当前模型版本；
- DeepSeek 模型连通性；
- 格式能力矩阵；
- 上传限制；
- 默认索引 profile；
- 服务健康；
- 密钥是否已配置（只显示 configured/not configured，不回显值）；
- 配额与速率限制；
- 审计导出。

管理员页面不得允许在浏览器中输入或显示完整上游 API Key。

## 9. 核心交互逻辑

### 9.1 上传交互

| 触发 | 前端行为 | 后端行为 |
| --- | --- | --- |
| 选择文件 | 本地校验并展示摘要 | 无 |
| 拖入有效文件 | dropzone 高亮，松手后校验 | 无 |
| 选择多文件 | V1 提示逐份提交；P1 排队队列 | 批量会话 |
| 格式不支持 | 就地错误，不创建上传会话 | — |
| 格式可解析不可建图 | 弹出能力选择 | 接收 profile |
| 上传中断 | 保留状态和重试入口 | 会话按过期策略清理 |
| 上传成功 | 显示“已校验，正在排队” | 创建 job |

### 9.2 任务进度交互

- 进度只增不减，除非切换到新的 attempt；
- 阶段条先显示全部阶段，不预判成功；
- 警告和失败使用不同视觉语义；
- 页面刷新可从服务端恢复；
- SSE 断线后自动降级到轮询，并显示“实时更新已降级”的小提示；
- 页面隐藏时不持续高频轮询；
- 完成后刷新文档图数据，不要求用户手动刷新。

### 9.3 图谱交互

| 操作 | 结果 |
| --- | --- |
| 单击节点 | 选中、右侧检查器更新、邻接边高亮 |
| 双击节点 | 展开一层邻居（最多 2 层） |
| 拖拽节点 | 调整视觉位置，不修改后端图谱 |
| 滚轮 | 缩放画布 |
| 点击空白 | 清除选择 |
| 点击边 | 显示关系类型、方向、evidence |
| 类型筛选 | 重新布局或淡出不符合节点 |
| 定位原文 | 打开证据抽屉并高亮 |
| 输入法/键盘 | Tab 选择节点，Enter 打开详情 |

节点布局位置属于视图状态，不持久化到图谱快照。

### 9.4 问答交互

| 状态 | UI |
| --- | --- |
| 空闲 | 显示 scope 和输入框 |
| 提交中 | 用户消息立即出现，系统显示检索步骤 |
| 流式生成 | 答案增量渲染，发送按钮变成停止 |
| 完成 grounded | 显示答案和引用 chips |
| 完成 insufficient | 显示拒答说明和“调整问题/扩大范围” |
| 429 | 显示冷却时间，不丢失问题 |
| 超时 | 保留问题，显示重试 |
| 引用点击 | 不跳离问答页，在右栏打开证据 |
| 多轮追问 | 保留 scope，只把必要的最近问题传给 Agent |

### 9.5 筛选与 URL 状态

以下状态应写入 URL，便于刷新和分享：

- 文档筛选条件；
- 文档详情 Tab；
- 图谱 scope、type filter、selected node；
- 问答 conversation_id；
- 任务状态筛选。

不应写入 URL：

- 访问 Token；
- 文件对象签名 URL；
- 完整 evidence 正文；
- 含敏感数据的 prompt 或日志。

### 9.6 删除、重索引与并发

- 同一文档已有 active job 时，“重新索引”变为“查看当前任务”；若强制创建，后端返回 409。
- 删除进行中任务需二次确认，文案明确是否取消远端任务。
- 删除后立即从列表和图谱 scope 中移除。
- 对于 `indexed` 文档，重索引不阻塞当前问答，直到新快照原子切换。

### 9.7 键盘与无障碍

- 所有按钮、Tab、文件选择器可键盘访问；
- Esc 关闭抽屉/对话框；
- 焦点不会被困在图谱 canvas 内；
- 提供可搜索的实体列表作为图谱的等价信息入口；
- 状态变化使用 `aria-live`，但不能每秒朗读进度；
- 颜色之外还使用图标、文本和形状区分状态。

## 10. UI 布局、视觉与响应式规范

### 10.1 视觉方向

关键词：专业、研究型、可信、低干扰、证据优先。

视觉语言采用深色知识工作台风格：

- 主背景深海军蓝，减少长文档阅读疲劳；
- 主内容使用清晰层级和低对比边框；
- 蓝色代表主要操作，青绿色代表成功/可信；
- 橙黄色只用于待处理/质量警告；
- 红色只用于失败、删除和危险操作；
- 图谱节点用语义色，但还要有图例和文字标签。

- 按钮/输入框圆角 8–10 px；
- 大面板圆角 14–16 px；
- 阴影只用于浮层：`0 16px 48px rgba(0,0,0,.28)`；
- 页面内部卡片优先用边框和层级色，不用重阴影。

### 10.5 桌面布局

#### ≥ 1440 px

```text
┌────── 240px ──────┬──────────────────────── content ─────────────────────────┐
│ Logo + workspace  │ Header: 面包屑 / 操作 / 用户                            │
│ 工作台            ├──────────────────────────────────────────────────────────┤
│ 文档              │ 主内容区（最大 1440px 或自适应）                         │
│ 图谱              │ 主列表/画布 + 360px 右侧检查器                           │
│ 问答              │                                                          │
│ 任务              │                                                          │
│ 管理              │                                                          │
└───────────────────┴──────────────────────────────────────────────────────────┘
```

#### 1024–1439 px

- 左侧导航压缩到 72 px 图标轨道；
- 右侧检查器默认 320 px；
- 图谱画布最小 560 px；
- 文档表格可隐藏次要列。

### 10.6 平板布局

768–1023 px：

- 侧边栏变图标抽屉；
- 文档详情使用单列内容，检查器改为右侧 Sheet；
- 问答页保持“会话 + 输入”，原文证据改抽屉；
- 指标卡 2–3 列；
- 图谱画布高度至少 480 px。

### 10.7 手机布局

< 768 px：

- 顶部品牌栏 + 底部五项导航：工作台、文档、图谱、问答、任务；
- 上传区纵向排列；
- KPI 卡 1–2 列；
- 表格改为卡片列表；
- 图谱使用全屏模式，详情为底部 Sheet；
- 问答采用单列，证据点击后打开全屏抽屉；
- 主按钮触控高度 ≥ 44 px；
- 文件名、错误详情允许换行；
- 不提供复杂拖拽编辑图谱，保留点按与缩放。

### 10.8 动效

- 页面切换 160–220 ms；
- 进度条 300–400 ms ease-out；
- 右侧抽屉 220 ms；
- 图谱选中高亮 120 ms；
- 不使用持续闪烁提醒；
- 尊重 `prefers-reduced-motion`，缩短或关闭非必要动画。

## 11. 组件规范

### 11.1 App Shell

- 品牌标识、工作区切换（P1）、主导航、用户菜单；
- 主内容有明确最大宽度；
- 固定 Header 仅在长页面出现；
- 移动端不固定过多层级，避免占用阅读空间。

### 11.2 上传 Dropzone

状态：

`idle, dragover, selected, validating, uploading, error, complete`

要求：

- 同时支持点击和拖拽；
- 显示支持格式和当前模式；
- 选中后显示文件名、大小和能力标签；
- 上传进度与解析任务进度分开；
- 错误在组件内展示，不只用 Toast。

### 11.3 状态徽标

| 状态 | 文案 | 视觉 |
| --- | --- | --- |
| uploading | 上传中 | 蓝色 + 进度 |
| queued | 排队中 | 灰色 |
| parsing | 解析中 | 蓝色/黄色 |
| extracting | 抽取中 | 蓝色 |
| graph_building | 建图中 | 紫色/蓝色 |
| indexed | 可问答 | 绿色 + 对勾 |
| parse_ready | 仅解析完成 | 青色 |
| failed | 失败 | 红色 + 错误图标 |
| cancelled | 已取消 | 灰色 |

### 11.4 阶段进度条

- 已完成为实心；
- 当前阶段为脉冲描边（低强度）；
- 未开始为空心；
- 失败阶段显示断开和错误图标；
- hover 或点击显示该阶段开始/结束时间；
- 不显示无法由 API 保证的精确剩余时间。

### 11.5 数据卡片

- 标签、主数值、趋势/状态说明；
- 数字使用等宽数字特性；
- 单位必须显示；
- 无数据用“—”，不得用 `0` 表示未知。

### 11.6 数据列表/表格

- 表头支持排序时显示明确图标；
- 行高 48–56 px；
- 主列是文件名/实体名；
- 状态、类型使用徽标；
- 行内操作最多 2 个，其他放菜单；
- 空状态与无搜索结果状态区分。

### 11.7 筛选栏

- Search、Select、Multi-select、Date range；
- “清除全部”仅在存在筛选时出现；
- 筛选条件可写入 URL；
- 桌面单行，移动端折叠为 Filter Sheet。

### 11.8 Graph Canvas

- 必有图例；
- 必有缩放、重置和全屏；
- 选中节点具有形状/描边差异；
- 缺少 bbox 的节点不显示虚假高亮；
- 节点标签在缩放阈值以下可隐藏；
- 300 节点以上进行分页/子图，不一次性渲染全部。

### 11.9 证据卡片

- 文档名、文件名、页号；
- evidence 原文；
- `page_idx`、`char_interval`、bbox 可选展示；
- 来源类型：节点、边、页文本、表格；
- 操作：定位原文、复制引用、打开图谱节点。

### 11.10 对话消息

| 元素 | 规范 |
| --- | --- |
| 用户消息 | 右侧或高对比气泡 |
| 系统答案 | 左侧宽卡片，正文可复制 |
| grounded | 绿色“有引用” |
| insufficient | 灰色/黄色“证据不足” |
| tool trace | 默认折叠，管理员可展开 |
| citation | 可点击 chip，编号稳定 |
| retry | 原位重试，不新增重复用户消息 |

### 11.11 Toast、Banner、Dialog

- Toast：2–4 秒，非阻塞，最多 1 个；
- Banner：持续存在，用于服务降级/任务告警；
- Dialog：权限、删除、切换 profile 等破坏性操作必须明确操作对象；
- 危险按钮不使用主色；
- 长错误信息放详情抽屉，不塞入 Toast。

### 12.2 页面字段读取规则

- 文档是否可问答只看 `status=indexed` 且存在 active snapshot；
- `progress` 只展示，不能决定成功；
- 引用展示只消费 `citations[]` 中服务端校验通过的条目；
- `grounded=false` 时不显示“已验证”标识；
- `warnings[]` 在答案/详情中展示，不覆盖主内容；
- `used_documents` 用于说明本次问答 scope；
- `tool_trace` 默认折叠，普通用户不展示敏感参数；
- 上传阶段展示的值来自上传会话状态，解析后使用 `GET /documents/{id}` 真值；
- `bbox` 和 `bbox_pdf` 必须带坐标系语境，前端不自行猜测；
- `page_idx` 是 0 基，用户界面页号默认显示 `page_idx + 1`。

### 12.3 问答态到 UI 映射

| --- | --- |

| `GRAPH_NOT_READY` | 禁用问答 + 跳转任务 |

## 13. 权限、安全与异常体验

### 13.1 权限矩阵

| 能力 | 查看者 | 分析师 | 运营 | 管理员 |
| --- | --- | --- | --- | --- |
| 查看已授权文档 | 是 | 是 | 是 | 是 |
| 上传 | 否 | 是 | 是 | 是 |
| 提问 | 是 | 是 | 是 | 是 |
| 下载普通产物 | 按策略 | 是 | 是 | 是 |
| 重索引 | 否 | 可选 | 是 | 是 |
| 删除 | 否 | 可选 | 是 | 是 |
| 查看诊断日志 | 否 | 否 | 是 | 是 |
| 管理连接和配额 | 否 | 否 | 否 | 是 |

### 13.2 敏感信息

前端不得：

- 显示 MinerU Token 或 DeepSeek Key；
- 展示完整对象存储路径和签名；
- 在页面、URL、日志、埋点中记录完整 prompt 和全文；
- 将错误堆栈直接展示给普通用户；
- 将内部绝对路径写入可复制诊断文本。

### 13.3 标准错误体验

每个错误展示三层：

1. **用户语言**：发生了什么；
2. **可执行动作**：重试、取消、更换文件、联系管理员；
3. **技术信息**：仅授权用户展开，显示 `code/request_id/job_id`，不显示敏感内容。

### 13.4 空、加载与部分失败

| 场景 | 表现 |
| --- | --- |
| 首次空文档库 | 引导上传 |
| 无搜索结果 | 保留筛选和清除操作 |
| 加载 | Skeleton，不使用无限旋转盖住全页 |
| 局部失败 | 保留可用模块，标注失败模块 |
| 部分页抽取失败 | 显示“部分成功”，禁用受影响页引用并保留其他结果 |
| SSE 断线 | 自动降级轮询，不弹全屏错误 |
| 文档删除中 | 变为只读，禁止提问 |

## 14. 非功能要求

### 14.1 性能

- 首屏 JS/CSS gzip 后建议 ≤ 400 KB；
- 图谱超过 300 节点进行分页/子图；
- 列表使用虚拟滚动或分页；
- 证据抽屉首次打开 ≤ 500 ms（已有数据）；
- 页面状态恢复不触发重复上传或重复 job；
- 移动端图谱避免持续高帧率物理模拟，交互稳定后停止重绘。

### 14.2 可靠性

- 上传与任务状态可恢复；
- SSE 断开有降级；
- 前端刷新不重复创建完整上传会话，除非会话已过期；
- 引用点击使用可重试的资源请求；
- 删除和重索引防止重复提交。

### 14.3 安全

- CSP 限制脚本来源；
- 对 evidence、Markdown、文件名做 HTML 转义；
- 禁止 `innerHTML` 直插未经清洗的模型输出；
- 签名 URL 不放 Referer、URL 和日志；
- 文件预览与主应用不同源或使用安全沙箱；
- CSRF 策略与令牌存储方式由身份方案统一；
- 所有 API 调用依赖服务端授权，不依靠前端隐藏按钮。

### 14.4 可访问性

- WCAG 2.1 AA 目标；
- 正常文本对比度 ≥ 4.5:1；
- 焦点清晰；
- 图标按钮有 aria-label；
- 颜色不单独承载状态；
- 键盘可完成上传、筛选、问答、引用查看；
- 动画支持 reduced-motion。

### 14.5 国际化与文案

- V1 中文优先；
- 所有文案集中管理，不散落硬编码；
- 页号区分显示页号与 0 基 `page_idx`；
- “可建图 / 仅解析 / 暂不支持”术语固定，不在不同页面变化；
- “证据不足”是正常业务结果，不能写成系统失败。

## 16. 风险、边界与后续演进

### 16.1 主要风险

| 风险 | 影响 | 产品应对 |
| --- | --- | --- |
| 上游 MinerU/LLM 不稳定 | 上传后长时间失败 | 状态透明、重试、错误码、保留已完成阶段 |
| 多格式产物结构不同 | Office/图片建图质量不一致 | 能力分级、Normalizer 验收门槛 |
| 图谱抽取噪声 | 标题/题注进入图谱 | 质量筛选、丢弃原因、后续 prompt/过滤优化 |
| 问答幻觉 | 用户得到无依据结论 | 强制 citation 校验、无证据拒答 |
| 页面引用无法定位 | 用户信任下降 | 区分“有文本证据/有 bbox”两种状态 |
| 文档含 Prompt Injection | Agent 被文档内容诱导 | 文档内容标记为不可信、scope 强控 |
| 大图谱卡顿 | 画布不可用 | 子图、分页、虚拟化、300 节点阈值 |
| 密钥泄漏 | 严重安全风险 | 后端 Secret Manager、日志脱敏、前端永不持有 |

### 16.2 V1 明确边界

- Agentic-RAG 当前不使用 Embedding；
- 图谱召回和页文本关键词是主检索策略；
- “多模态”当前是多格式文档解析，不是图片语义问答；
- Graph V1 只有 PDF 完成实测；
- 当前问答 MVP 的内容是内联引用，前端上线结构化引用前必须完成后端适配；
- `full.md` 只作预览，不保证完整；
- 图谱可视化位置是视图状态，不代表文档真实空间坐标；
- 图谱节点位置与 PDF bbox 是两套不同坐标，不可混用。

### 16.3 产品成功判定

产品达到 V1 可交付状态，需要同时满足：

1. 一份 PDF 能稳定从上传走到 indexed；
2. 用户能在结果页理解解析和抽取质量；
3. 用户能提问并获得至少一条可验证引用；
4. 点击引用可在证据面板查看原文；
5. 无证据时系统明确拒答；
6. 失败任务可解释、可重试；
7. 任意页面均不暴露密钥；
8. 桌面、平板、手机均可完成核心流程。
